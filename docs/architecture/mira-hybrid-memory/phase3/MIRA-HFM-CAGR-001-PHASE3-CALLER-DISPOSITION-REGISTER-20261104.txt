7. PRIORITY AND PHASE 3 EXIT CONDITIONS
P0 — no autonomous or cross-project use until scoped:
- Core Knowledge/Memory read APIs; CRM conversation/message context; model-facing conversation context; Work Learning/Experience/Work Knowledge and cross-task/opportunity consumers; Google Drive whole-file read.
P1 — privileged, governed operation only:
- Admin proposal/apply; human-only cleanup; controlled apply/evolution; snapshot/restore/recovery; audit/proposal stores; learning history admin read.
P2 — separate domain review:
- Capacity utility, research governance, and generic application stores not shown to be canonical Memory.

Phase 3 cannot be declared complete merely because the synthetic contract tests pass. Required before completion:
1. Trusted host authentication adapter and replay protection contract integrated and tested in a fixture-backed host harness.
2. Authoritative project/owner registry design for General Memory, Knowledge and CRM; no default project assignment.
3. Explicit project/task authority and projection lineage contract for Work Learning, Experience and Work Knowledge, or formally exclude them from v0.2 migration scope with a governed alternative.
4. Caller inventory extended to dynamic/indirect imports, provider callbacks, caches, exports, embeddings, background workers and backup/restore.
5. Route/tool/store bypass negative tests for every P0 reader and every privileged P1 path.
6. Independent regression, integrity and recovery tests; no production data migration or provider cutover without separate approval.
