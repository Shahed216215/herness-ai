3. MODEL-PROVIDER DATA EGRESS

services/ai.js delegates generation to providers/index.js. providers/index.js chooses configured provider and may make one configured fallback attempt after a transient error. Provider execution attempts are audit-recorded. The prompt supplied to generate() is passed to the selected provider; therefore application prompt/source content may leave the local process when a live provider call is made.

Provider transport patterns observed:
- OpenAI, Gemini, Groq use secureSdkFetch with host allowlist: api.openai.com, generativelanguage.googleapis.com, api.groq.com.
- Anthropic, DeepSeek, OpenRouter, Hugging Face, xAI use secureProviderRequest with fixed provider endpoints.
- Custom provider slots 1–5 use secureProviderRequest with configured/environment URLs and optional bearer credentials.
- Custom providers 1–5 can transmit the full prompt and system instruction fields to the configured endpoint.
- services/learning.js sends source content to the configured AI provider for structured knowledge extraction; this is provider egress, not local-only processing.
- tools/web-search.js sends search query and Tavily API key to https://api.tavily.com/search through secureProviderRequest. Tavily results are external retrieval, not a durable Memory store.

No outbound request was made during this review.

4. TRANSPORT SECURITY OBSERVATIONS

secureSdkFetch restricts HTTPS, a fixed hostname allowlist, GET/POST methods, and disabled redirects, then delegates to secureProviderRequest.

secureProviderRequest and provider-url-policy enforce HTTPS for public endpoints, reject URL credentials/fragments, block local names by default, resolve hostnames, reject private/special-use IPs unless an explicitly configured private-provider policy applies, and use pinned lookup behavior.

Custom provider modules pass allowPrivate=true only when MIRA_ALLOW_PRIVATE_CUSTOM_PROVIDER_URLS=true. The URL policy then permits selected private endpoints; this is an explicit deployment configuration and must be reviewed as an egress/security exception. No such environment value was inspected.

services/custom-provider-config.js stores endpoint/name/model slots under MIRA_CUSTOM_PROVIDER_CONFIG_PATH or process.cwd()/data/custom-provider-slots.json. It requires HTTPS and rejects URL credentials, query, fragments, and many private/local host forms. Its file path is not mira-storage by default.

Transport controls reduce SSRF/redirect risk but do not establish data minimization, provider retention policy, contractual privacy, prompt classification, or per-domain user consent.

5. CREDENTIAL GOVERNANCE

services/provider-credential-store.js uses AES-256-GCM and scrypt-derived key material and requires MIRA_CREDENTIALS_ENCRYPTION_KEY with at least 32 UTF-8 bytes. Its default path is project-root data/provider-credentials.enc.json, not mira-storage.

routes/mira-provider-evolution.js exposes provider credential metadata, write, reveal, and delete routes. server.js mounts this router behind requireAdminPermission(PERMISSIONS.SYSTEM_ADMIN). The metadata route avoids returning plaintext key values and sets no-store headers. PUT requires encryption readiness and returns activated=false. Reveal writes an audit attempt before reading the managed credential and writes a success audit after; it returns plaintext key in the response. DELETE is also present. These are privileged credential-management actions, not Memory-provider permissions.

No secret value, token, or credential file was read. The fact that the route is admin-gated does not prove operational policy, session security, or external provider consent is fully adequate.

8. MEMORY/LEARNING ROUTE INTEGRATION OBSERVATIONS

- routes/conversations.js delegates to conversation-store and mira-conversation-memory-engine; conversation persistence is separate from general memory.json.
- routes/learning-history.js delegates to mira-learning-history and mira-experience-memory; this is derived learning-history/experience retrieval, not the General Memory store.

- routes/mira-research-governance.js delegates to Research Governance and task-store, with audit callback.
- routes/mira-provider-evolution.js uses the credential store and privileged admin routes.
- server.js mounts the provider evolution router behind SYSTEM_ADMIN permission middleware.
- mira-request-context.js selects at most 8 recent messages and 4,500 total chars by default; it is a bounded context selector, not durable long-term retrieval.
- mira-conversation-memory-engine.js extracts structured conversation context and persists via conversation-store.
- mira-experience-retrieval-engine.js uses lexical token overlap and emits governance flags executable=false, modifiesCode=false, bypassesPolicy=false; it is not a token-budget-aware multi-source provider.
