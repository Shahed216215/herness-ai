===== CONFIRMED STORAGE OWNERSHIP =====
1. General Memory:
   Existing memory.js and Local Store use phone-local memory.json.
   This is a legacy dependency, not the approved future Hybrid backend.

2. Work Learning:
   services/mira-work-learning-engine.js owns work-learning-records.json
   or the configured MIRA_LEARNING_FILE path.

3. Experience Memory:
   Derived from Work Learning records.

4. Experience Retrieval:
   Derived retrieval layer over Experience Memory.

5. Future Strategy:
   Read-only derived layer over Experience Memory lessons.
   No direct persistence operations found in inspected source.

6. Cross-Task Learning:
   Depends on Experience Retrieval and Future Strategy.

7. Learning History:
   Derived from Experience Memory and Future Strategy.

8. Knowledge Consolidation:
   Owns data/work-knowledge-consolidation.json.

9. Conversation Memory:
   Uses Conversation Store, which owns data/conversations.json.

10. Knowledge:
    Uses knowledge.json and Google Drive integration.

11. Evolution:
    Has separate local writer, Drive synchronization and Snapshot Manager.
    It is not integrated with Local Memory Store.

===== CONFIRMED INTEGRATION GAPS =====
HFM-01 CRITICAL:
Phone-local General Memory dependency must be replaced through a verified
migration plan. Existing data must remain untouched until recovery and
dependency checks are complete.

HFM-02 CRITICAL:
Evolution and Local Store use different write/read/restore paths.
Evolution's private writer and Snapshot Manager restore do not use the
Local Store atomic writer and integrity readback contract.

HFM-03 CRITICAL:
A backend-neutral canonical Memory contract is not yet implemented.

HFM-04 HIGH:
Work Learning backend migration adapter is not implemented.

HFM-05 HIGH:
Knowledge Consolidation backend migration adapter is not implemented.

HFM-06 HIGH:
Conversation Store backend migration adapter is not implemented.

HFM-07 HIGH:
Knowledge and Google Drive lifecycle reconciliation remains necessary.

HFM-08 HIGH:
No Facebook connector was detected by the audited source patterns.
This is not proof that no integration exists outside the scan scope.

HFM-09 HIGH:
Tavily Web Search is a search provider, not a durable Memory backend.
Retrieval provenance and source verification contracts remain undefined.

HFM-10 HIGH:
Hybrid emergency backup and recovery design remains incomplete.

HFM-11 HIGH:
Conflict resolution, duplicate detection, versioning and source identity
policies require a unified contract.

HFM-12 HIGH:
Learning and Evolution governance integration requires further design.
