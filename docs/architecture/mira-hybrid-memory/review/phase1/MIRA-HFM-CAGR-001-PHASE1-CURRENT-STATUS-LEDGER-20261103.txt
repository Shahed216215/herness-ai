3. CURRENT EVIDENCE-BASED FINDINGS

- General Memory Store has strong atomic write/readback behavior, but missing primary memory.json is interpreted as [].
- Knowledge load converts missing, malformed, and non-array state to [] and Knowledge CRUD writes directly without equivalent atomic/readback safeguards. HFM-001 and HFM-002 remain critical.
- Knowledge search currently allows any Drive array, including empty, to replace Local search data. The Phase 1 data-class authority/conflict policy is now recorded; the current code has not yet been changed to enforce that policy.
- Ordinary Knowledge/Learning CRUD performs local write then Drive sync; partial success and split-brain are possible.
- Knowledge backup/restore independently construct Google OAuth clients and use project-root paths; restore can overwrite data. Neither tool was invoked.
- Controlled apply and Evolution depend on Drive preflight, snapshots, verification, rollback, and recovery. Drive sync removal is blocked.
- MIRA_STORAGE_DIR does not contain every path: several overrides, provider credentials, snapshots, and legacy Knowledge tools use separate roots.
- AI and web-search provider calls can transmit prompts/source material outside the local process. No provider call was made.
- Google OAuth effective scopes cannot be inferred from reviewed source and remain unknown.
- No Facebook/Meta/Graph API connector-named path exists in the current branch tree. This is path-level evidence only; the JavaScript-family lexical source scan is complete, but no Facebook connector path was found.
- No production Memory data, credential values, or token files were accessed.
- Knowledge Improvement Apply has handled early-return failure branches without corresponding route-level audit records; lower-level audit coverage remains to be traced.
- Knowledge Improvement's audit helper swallows audit-store errors, while Autonomous Learning's helper does not; consistent audit failure policy is not established.
- services/learning.js learnFromContent calls generate with source content, then may call addLearning directly; this can persist Knowledge and trigger Drive sync. The direct tools/learning-save caller is mapped; the policy distinction between ordinary educational ingestion and system-change proposals, plus consent enforcement, remains a future implementation requirement.
- The reviewed Experience Memory module derives projections from Work Learning Records and contains no independent persistence path.
