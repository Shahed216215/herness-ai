4. AUTONOMOUS WORKER — STARTUP, OPT-IN, AND PERSISTENCE
server.js imports startAutonomousWorker and calls it after the HTTP server listen callback. The worker is therefore part of the server startup path.
services/mira-autonomous-worker.js has an explicit opt-in:
- MIRA_AUTONOMOUS_WORKER_ENABLED must equal "true"; otherwise it returns disabled.
- MIRA_AUTONOMOUS_WORKER_INTERVAL_MS is bounded to 10,000–300,000 ms; default is 30,000 ms.
- On opt-in, it starts an interval and immediately invokes runOnce().
- A second opt-in, MIRA_AUTONOMOUS_RESEARCH_ENABLED, is required for the research branch.
- It processes at most one task per tick and uses low-risk/new task selection in the inspected path.
Persistence and side effects:
- Worker result JSONL: MIRA_WORKER_RESULTS_FILE override, otherwise storagePath("data/autonomous-worker-results.jsonl").
- Research budget: storagePath("data/autonomous-research-budget.json").
- Research reports: storagePath("reports") with a task-derived filename.
- It reads/writes the budget file, appends worker result records, writes research reports, and updates task status through task-store.
- task-store itself uses MIRA_TASK_FILE override or storagePath("data/tasks.json").
This adds worker output, research budget, reports, and task status to the persistence/caller inventory. The worker was not started or invoked during this review. No network search or task execution was performed.
