1. BASE STORAGE RESOLVER

mira-storage.js:
- Project root = path.resolve(__dirname).
- MIRA_STORAGE_DIR, when configured, changes STORAGE_ROOT to path.resolve(value).
- storagePath(relativePath) rejects absolute paths and traversal outside STORAGE_ROOT.
- If configured root target is missing, it may seed from the project-root counterpart when source is a regular non-symlink file, size-bounded, and not in excluded secret patterns.
- Excluded seed patterns include client_secret*.json and google-token.json.
- A shared path resolver does not automatically redirect code that uses __dirname, process.cwd(), PROJECT_ROOT, BASE_DIR, or a hardcoded path.

4. ROOT DIVERGENCE REGISTER

DIVERGENCE A — MIRA_STORAGE_DIR does not control every path:
- MIRA_MEMORY_FILE is an independent absolute path override.
- MIRA_AUDIT_FILE, MIRA_LEARNING_FILE, MIRA_STAGE13_STORE, MIRA_STAGE13_CAPABILITY_INTEGRATION_STORE, MIRA_STAGE16_17_WORKFLOWS_FILE, MIRA_WORKER_RESULTS_FILE, MIRA_TASK_FILE, MIRA_OPPORTUNITY_FILE, MIRA_RESEARCH_GOVERNANCE_FILE, MIRA_CHANGE_FILE, and MIRA_CAPABILITY_PROFILE_FILE may override individual files outside the shared root if absolute paths are configured.
- provider-credential-store uses __dirname project-root data path.
- custom-provider-config uses process.cwd() data path or MIRA_CUSTOM_PROVIDER_CONFIG_PATH.
- provider runtime/staging route uses project-root configuration files.
- snapshot-manager uses project-root backups/changes.
- legacy Knowledge tools use BASE_DIR/project-root paths.
- Google OAuth credentials use project-root and /etc/secrets fallback paths.

DIVERGENCE B — shared path resolver does not unify schemas or write guarantees:
- Local Memory Store has atomic temp/fsync/rename/readback.
- Knowledge CRUD uses direct writes.
- Conversation, Learning, Governance, Consent, and other stores each have their own persistence semantics.
- Path convergence alone does not establish one canonical provider or transaction model.

DIVERGENCE C — app data versus project recovery artifacts:
- backups/changes and staged artifacts are project/code recovery state and should not be merged into personal Memory.
- provider runtime configuration and credentials are privileged security state.
- proposal/approval records are governance state.
- client profiles/communications/consent are client data with separate access/retention rules.
