2. SOURCE SCAN RESULTS

2.1 Memory and persistence roots
- General Memory is rooted in services/mira-local-memory-store.js, with MIRA_MEMORY_FILE as an independent absolute-path override.
- Knowledge uses mira-storage through knowledge.js, but legacy Knowledge backup/cleanup/restore tools construct project-root paths directly.
- Conversation Store is a separate data/conversations.json domain.
- Work Learning Records use MIRA_LEARNING_FILE or data/work-learning-records.json.
- Work Knowledge Consolidation uses data/work-knowledge-consolidation.json.
- Stage13 Learning Governance uses MIRA_STAGE13_STORE or data/stage13-learning-governance.json.
- Audit Log uses MIRA_AUDIT_FILE or storagePath(audit-log.json).
- Research Governance uses MIRA_RESEARCH_GOVERNANCE_FILE or its storagePath default.
- Custom provider config, provider credentials, snapshot artifacts, client stores, opportunity/task/project stores, SEO workflow history, and autonomous orchestration each have separate persistence paths.
- Several overrides or legacy modules bypass the shared storage resolver; see prior Path Compatibility, Worker/Store, Domain Caller, and Persistence Compatibility reports.

2.2 Drive and Knowledge callsites
- Shared Google Drive adapter: google-drive.js.
- Direct OAuth clients: tools/knowledge-backup.js and tools/knowledge-restore.js.
- Knowledge CRUD callers: knowledge.js addKnowledge/addLearning/deleteKnowledge/updateKnowledge/updateLearning; tools/knowledge-save.js; tools/learning-save.js; controlled apply services; Evolution.
- Search caller: tools/knowledge-search.js; Drive array including [] replaces the local search source.
- Cleanup caller: tools/knowledge-cleanup.js; project-root direct write then Drive sync.
- Backup caller: tools/knowledge-backup.js; rewrites project-root knowledge.json, writes local backup, then direct Drive backup.
- Restore caller: tools/knowledge-restore.js; can replace project-root Knowledge and sync Drive.
- Work-derived consolidation and learning records remain separate from Knowledge CRUD and create governance proposals rather than being one canonical store.
- D01-D27 and all direct route/tool call paths are registered in the preceding reports; all-module lexical scan was used to find additional candidate references. Runtime reachability of every dynamic path remains a separate proof obligation.

2.3 Provider and external egress
- providers/index.js selects provider modules and may fall back according to runtime policy.
- Provider adapters include OpenAI, Anthropic, Gemini, Groq, DeepSeek, OpenRouter, Hugging Face, xAI, and custom provider slots 1–5.
- Shared secure transport is services/security/secure-provider-request.js; SDK wrapper is services/security/secure-sdk-fetch.js.
- Learning service sends source content to generate().
- tools/web-search.js sends query material to Tavily.
- Custom provider endpoints can receive prompts/source content when selected.
- Google Drive OAuth is a separately reviewed fixed-host exception; effective token scopes remain unknown.
- No live provider, Drive, or Facebook API call was made.

2.4 Audit and governance
- audit-log.js is the shared hash-linked audit store, with MIRA_AUDIT_FILE override.
- Several service/route helpers have different audit failure semantics (swallowed versus propagated).
- Knowledge Improvement Apply has early-return branches without route-level audit events; lower-level event coverage remains to be traced.
- Provider credential reveal route is SYSTEM_ADMIN-gated, returns plaintext credential material to the authorized response, and records audit attempts; no credential data was read.
- Client Consent is a separate persisted store; marketing and public research consent checks are separate.
- Work Learning, Experience Memory, Future Strategy, Cross-Task Learning, Learning History, and Knowledge Consolidation have distinct roles and provenance boundaries.

3.2 Candidate requiring an isolation wrapper
tests/mira-local-memory-safety-test.js:
- Sets MIRA_MEMORY_FILE to a temporary path before requiring Memory modules.
- It does not set MIRA_STORAGE_DIR itself.
- memory.js imports capacity-config.js, whose CONFIG_FILE resolves through mira-storage('capacity-config.json'). Without an externally supplied MIRA_STORAGE_DIR, a capacity-config.json in the checkout root could be read.
- No production Memory file is targeted by the test because MIRA_MEMORY_FILE is overridden, but full storage-root isolation should be enforced by launching it with MIRA_STORAGE_DIR pointing to a separate empty temporary directory. This is a test harness requirement, not a source patch.

- tests/stage121-122-earnings-profitability-e2e-test.js and tests/stage121-122-final-hardening-e2e-test.js temporarily replace existing earnings/cost data files and restore prior bytes; they are unrelated to Hybrid Memory and were not selected.

- Stage19 live transport, DNS/socket pinning, local TLS and SSRF tests were not run; they require their own controlled test harness/certificates and are outside this Phase 1 Memory fixture subset.
