DRIVE FINDINGS
1. google-drive.js provides Drive v3 read/write functions for Memory and Knowledge. The reviewed OAuth client construction does not pass an explicit scopes array; effective granted scopes cannot be established from source alone. Credential/token files were not accessed.
2. knowledge.js ordinary addKnowledge, addLearning, deleteKnowledge, updateKnowledge, and updateLearning persist locally then call syncToDrive. Drive errors are caught and represented as drive=false, so local success can coexist with Local/Drive divergence.
3. tools/knowledge-search.js reads Local first, then replaces its search source with any Drive array, including an empty array. This can mask non-empty Local Knowledge.
4. tools/knowledge-backup.js independently initializes Drive OAuth, writes project-root knowledge.json and knowledge-backup.json, then uploads/updates the backup in Drive. This is not a read-only operation and uses a separate Drive implementation.
5. tools/knowledge-restore.js independently reads Drive backup, validates backupVersion=1 and entries array, writes a safety backup, overwrites project-root knowledge.json, and attempts Drive synchronization. Destructive restore was inspected but not invoked.
6. tools/knowledge-cleanup.js directly writes project-root knowledge.json before calling saveKnowledgeToDrive.
7. knowledge-controlled-apply.js and autonomous-learning-controlled-apply.js require Local/Drive preflight agreement and use Drive write/readback verification and rollback.
8. knowledge-memory-evolution.js uses Drive read/write, persisted Drive snapshots, hash/equality verification, and rollback. This is a confirmed blocker to removing Drive sync before dependent workflows are migrated and verified.
9. tools/knowledge-save.js and tools/learning-save.js are indirect callers through Knowledge CRUD and services/learning.js.
10. tools/web-search.js calls Tavily through secureProviderRequest. This is general web search, not Facebook Memory retrieval.
11. providers/index.js routes configured model-provider requests and can attempt one configured fallback. This is model inference, not a unified Memory provider contract.
12. Provider credential storage uses AES-256-GCM and scrypt-derived key material. Its default file path is project-root data/provider-credentials.enc.json, not mira-storage. No credential values were read.
