5. RESIDUAL RISK / FOLLOW-UP REGISTER

R01 — Knowledge read/write safety
- knowledge.js maps missing, malformed, and non-array Knowledge JSON to [].
- Knowledge CRUD uses direct writes rather than the Local Memory Store's atomic temp/fsync/rename/readback pattern.
- Ordinary CRUD can write Local successfully and then report Drive sync failure, leaving partial dual-write state.
- Severity: HIGH.
- HFM-001/HFM-002 remain open for future implementation.

R02 — Evolution writer duplication
- Knowledge/Memory Evolution uses its own writer; Local Memory Store is separate.
- Severity: HIGH.
- Requires compatibility design, isolated regression tests, and approved migration before consolidation.

R03 — Storage root divergence
- MIRA_STORAGE_DIR does not control every file path.
- Legacy Knowledge tools, provider credential/config stores, snapshot manager, and several explicit path overrides can remain outside the shared root.
- Severity: HIGH.
- Must be addressed with per-domain migration and rollback plan, not a blanket path rewrite.

R04 — Missing schedule store
- services/mira-project-schedule-planning-service.js and Stage 9.2.5 tests reference ../project-schedule-store.
- No matching module or path history was found in the reviewed branch; historical service source already contained the broken import at initial public upload.
- Expected MODULE_NOT_FOUND when those paths are loaded.
- Severity: HIGH for affected schedule service/tests; no proof main server startup is blocked.

R05 — Drive dependency
- Controlled apply, autonomous learning apply, Knowledge tools, and Evolution still depend on Drive.
- Drive sync removal remains prohibited until a tested replacement and separate cutover approval exist.

R06 — Provider account configuration
- Effective Google OAuth scopes, ZDR/account settings, custom provider vendors/terms, and some downstream provider retention are unknown.
- No credential/token content was accessed.
- Live provider usage with sensitive Memory/Knowledge requires separate account-level verification and data-minimization controls.

R07 — Facebook connector absence
- No Facebook Page/Group Graph API connector path was found in the reviewed source tree.
- The target Page/Group authority policy is a design baseline only; no Facebook connector, publication, or private Group access exists from this work.

R08 — Audit consistency
- Knowledge Improvement and Autonomous Learning apply routes differ in audit failure propagation and early-return coverage.
- A common audit failure policy is not established.

R09 — Runtime completeness
- Source inventory and static lexical scans do not prove every dynamically computed path, plugin, or indirect runtime caller.
- Runtime workers/routes were not started or invoked.
