FINDING
The dynamically registered tool tools/memory-version-recovery.js exposes list, verify and restore actions. Its tool name memory_version_recovery had no explicit entry in services/mira-work-execution-engine.js TOOL_POLICIES. The engine already failed closed for tools with no policy (unknown_tool), so this was not an observed bypass. It was a policy-coverage/documentation gap.

CHANGE
Added an explicit human-only policy entry:
- operation=file_modify
- autonomous=false
- humanApprovalRequired=true
- explicitConfirmation=true

The entire wrapper is blocked from autonomous execution for now. This is intentionally conservative because the current engine does not carry an action-scoped authenticated approval token; a single tool-level policy cannot safely distinguish read-only list/verify from destructive restore. Human-only classification preserves the prior fail-closed runtime behavior while making the boundary explicit. No tool action or restore was executed.

TEST
Added tests/mira-hfm-memory-version-recovery-policy.test.js. It is dependency-free and statically verifies:
- the wrapper exposes the expected registered tool identity/declaration/executor;
- an explicit policy exists;
- autonomous execution is false;
- human approval and explicit confirmation are required;
- unknown tools remain rejected by the engine source contract.
