17. RESOLVED-CONFLICT RETRIEVAL SELECTION HARDENING — 2026-11-04

Finding:
- filterTrustedRecords() previously blocked originals while a conflict was QUARANTINED or UNDER_REVIEW, but listConflicts() did not expose the selected resolution digest to the retrieval filter.
- After ACCEPT_EXISTING_VERSION, ACCEPT_ALTERNATE_VERSION or REJECT_CONFLICTING_CHANGE, the conflict status became RESOLVED/REJECTED and the previous filter no longer blocked any original. Multiple conflicting versions could therefore become retrievable again.
- APPROVED_FIELD_MERGE also needed to keep all source originals excluded after resolution.

Correction:
- listConflicts() now exposes the original record digests, resolution decision, accepted original digest and resulting merge digest only from a verified resolution record.
- filterTrustedRecords() now:
  - blocks every original while quarantined, under review, retained or integrity-failed;
  - after a selected-version resolution, permits only the exact accepted original digest and excludes every unselected original;
  - after an approved merge, excludes all original digests so only the separately persisted merged record can be retrieved;
  - fails closed for malformed, incomplete, unknown or unsupported conflict metadata.
- No legacy record identity, project mapping or resolution authority was inferred.

Regression tests:
- Resolved accepted version only retrievable.
- REJECT_CONFLICTING_CHANGE excludes the unselected original.
- ACCEPT_ALTERNATE_VERSION selects the exact requested original.
- APPROVED_FIELD_MERGE excludes all source originals.
- Incomplete resolution metadata and malformed conflict metadata fail closed.
