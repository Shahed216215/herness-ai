1. ADDITIONAL PERSISTENT-WRITER DEFENCE

The shared policy check was already enforced by tools/index.js executeTool(). The exported raw tools map, however, allows trusted application code to call a module's execute() method directly without passing through executeTool().

To close that specific bypass for the three persistent-write wrappers, added a second policy check at the beginning of each wrapper:
- tools/memory-save.js — memory_save
- tools/knowledge-save.js — knowledge_save
- tools/learning-save.js — learning_save

Each wrapper now invokes checkToolSafety() before validating or using persistence dependencies. Under the current human-only policies, the wrapper returns a structured BLOCKED / TOOL_POLICY_DENIED response and does not call addMemory(), addKnowledge(), or learnFromContent().

No generic chat argument, permissionGranted flag, or wrapper argument can turn this denial into approval. These tools remain unavailable for autonomous or generic direct execution until a genuine authenticated action-scoped approval contract is implemented.
